# 微信接龙消息转发

接龙使用外层消息类型 `49`、应用子类型 `53`。此前 SDK 对该子类型返回 `undefined`，bot 未进入转发分支，WebUI 将其记为 `unknown/excluded`。这不意味着微信服务没有收到消息。

修复后：

- SDK 返回 `Message.Type.Solitaire`（`solitaire`）；`text()` 提供完整的可见标题、编号名单和尾注。
- 原始 `Content`、`_text`、`_xml` 保留，不把内部 `solitaire_info`、用户标识或附件字段作为正文输出。
- bot 按现有群绑定转发为安全转义的文本；原有消息前缀、表情显示、长文本分片、接收开关和禁用自动建群策略保持生效。
- WebUI 保存可见正文，保留协议类型 49 和原始来源，新记录进入正常待同步状态，不再因未知类型直接排除。
- CDATA、XML 实体、前导零、Unicode 和换行不会因数字自动转换而损坏。无法安全解析时显示明确的接龙提示，不输出整段原始 XML。

## 在 Telegram 里直接接龙

群聊和单聊中的接龙转发时都会附带「参与接龙」按钮：

- 只有机器人主人可以点击；其他人点击会收到明确提示，不会发出任何微信请求。
- 按钮使用扁平键盘结构（`Option.inline_keyboard` 为按钮数组，由发送器自行包成一行）；发送前会丢弃无法渲染的按钮，键盘异常不会拖累正文送达。
- 点击后取你在该群的**群昵称**（群聊；没有则用微信昵称，单聊直接用微信昵称）作为追加内容，调用服务端 `POST /Msg/SendSolitaire` 的“参与”模式；服务端用 `MsgID` 或 `NewMsgID` 查找自己保存的那条接龙消息并拼 XML，客户端不传 XML、`Title`、`Tail`。
- 因此服务端需要开启本地消息保存（`savelocalmessage`，默认开启）并且该接龙消息已落库；未落库会返回明确错误，可在微信稍后重试。
- 署名规则：微信昵称本身可以是 `undefined`、`null` 这类字符串，属真实数据，照常写入；只有解析结果为空或类型缺失时才取消发送并提示。
- 结果分三种：成功、被服务端明确拒绝（显示原因）、结果不确定（提示到微信确认，**不会自动重发**，避免重复报名）。
- 按钮 30 分钟过期，最多保留 256 个；过期或跨账号一律拒绝。
- 长整型 `NewMsgID` 以原始数字写入请求体，避免 JavaScript 精度丢失。

## 自定义内容与发起接龙

- 接龙消息现在有两个按钮：「参与接龙」（用群昵称，单聊用微信昵称）和「自定义参与」。
- 自定义内容有两种输入方式：
  1. 直接发命令 `/join 2 份`（最快的富文本式直输，正文原样作为内容）；
  2. 点「自定义参与」后，机器人会发一条提示，**回复该提示**的纯文本即作为内容（不支持格式时的后备方式）。
- 自定义内容**完全替换**昵称，不会拼成“昵称，2 份”；需要署名就自己写进内容里。空内容会被拒绝。
- `/join` 不带内容时，会开启上述回复模式；目标默认是当前会话里最近一条接龙（30 分钟内有效）。
- 发起接龙：在已绑定微信群的 Telegram 群或 Topic 里执行
  `/solitaire 标题 | 首条内容 | 尾注`（尾注可省略）。单聊或未绑定会话会直接拒绝并给出用法。
- 参与和发起成功后**不再额外回复**：微信会把更新后的接龙当作一条普通接龙消息发出，机器人按原样转发，这就是成功的回执；被拒绝或结果不确定时仍会明确提示。
- 昵称可以是 `undefined`、`null` 这类字符串（真实数据）；只有解析结果为空或类型缺失时才取消发送。

普通回复仍不会自动追加到微信接龙名单；参与只发生在按钮、`/join` 或回复提示这三种明确操作下。

已保存的历史 `excluded` 接龙不自动重放或改变状态，避免误补发其他被用户关闭接收的内容。历史补发需确认具体会话及范围，另行处理。

测试使用真实 SDK 类型判定和 bot 消息分发，覆盖群目的地、完整名单、HTML 转义、源报文保留、关闭接收、未绑定会话以及 WebUI 入库状态。另已对已捕获消息做过只读解析重放验证；这不是把旧消息实际发送到 Telegram。
