# 微信接龙消息转发

接龙使用外层消息类型 `49`、应用子类型 `53`。此前 SDK 对该子类型返回 `undefined`，bot 未进入转发分支，WebUI 将其记为 `unknown/excluded`。这不意味着微信服务没有收到消息。

修复后：

- SDK 返回 `Message.Type.Solitaire`（`solitaire`）；`text()` 提供完整的可见标题、编号名单和尾注。
- 原始 `Content`、`_text`、`_xml` 保留，不把内部 `solitaire_info`、用户标识或附件字段作为正文输出。
- bot 按现有群绑定转发为安全转义的文本；原有消息前缀、表情显示、长文本分片、接收开关和禁用自动建群策略保持生效。
- WebUI 保存可见正文，保留协议类型 49 和原始来源，新记录进入正常待同步状态，不再因未知类型直接排除。
- CDATA、XML 实体、前导零、Unicode 和换行不会因数字自动转换而损坏。无法安全解析时显示明确的接龙提示，不输出整段原始 XML。

这只实现接收和显示，不会把 Telegram 的普通回复自动追加到微信接龙名单，也不会调用服务端的发起/参与接龙接口。

已保存的历史 `excluded` 接龙不自动重放或改变状态，避免误补发其他被用户关闭接收的内容。历史补发需确认具体会话及范围，另行处理。

测试使用真实 SDK 类型判定和 bot 消息分发，覆盖群目的地、完整名单、HTML 转义、源报文保留、关闭接收、未绑定会话以及 WebUI 入库状态。另已对已捕获消息做过只读解析重放验证；这不是把旧消息实际发送到 Telegram。
