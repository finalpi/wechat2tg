# 微信行内自定义表情

将微信消息中的 `[微笑]`、`[捂脸]`、`[旺柴]` 等原生表情文本替换成 [WeChatPack](https://t.me/addemoji/WeChatPack) 的 Telegram 自定义表情，和文字处于同一行，不另发图片、贴纸或图片链接。

## 开启与关闭

默认关闭。在 `.env` 设置以下值并重建 bot，或在 WebUI「消息转发」中开启「微信行内自定义表情」、保存后重启：

```dotenv
WECHAT_CUSTOM_EMOJI_ENABLED=true
```

开启后优先于原有 `emojiPicture` 图片链接开关，不改写该旧设置。关闭新开关后恢复原来的行为。不会修改微信服务配置、数据库 schema、论坛设置或会话绑定；安装更新本身不会自动修改部署端 `.env`。WebUI 保存的同名配置优先于环境变量。

## 发送资格

根据 [Telegram Bot API 的格式规则](https://core.telegram.org/bots/api#formatting-options)，机器人需要通过 Fragment 购买附加用户名，或者机器人创建者拥有 Telegram Premium（适用于机器人直接发送到私聊、群和超级群的消息）。接收方不需要 Premium。

本功能保持原来的机器人发送身份，不会切换成用户账号绕过限制。媒体的大文件 MTProto 路径同样以机器人身份发送，不绕过 Telegram 的资格检查。资格不满足时请关闭开关；不会因超时或不确定的发送结果自动再补发一条普通表情消息。

## 映射与范围

- 当前包有 115 张静态自定义表情；已根据实际图像与仓库中有名称的微信参考图片核对 **108 种表情、213 个中英文别名**。
- 只替换原生方括号文本，包括 `[Smile]`、`[Facepalm]` 等对应英文别名。原本输入的 `🙂`、`😂` 等普通 Unicode Emoji 原样保留。
- 包中有重复的普通 Emoji 标记，例如「微笑」和「皱眉」都标为 `🙂`，但文档 ID 不同。因此不按普通 Emoji 自动猜测映射。
- 目前未确认对应图像的 `[發]`、`[爆竹]` 保留原文；其他未知文本也不变。
- Telegram 要求 `<tg-emoji>` 内的回退字符与该文档绑定的原生 Emoji 一致。映射保留 API 返回的准确字符，包括变体选择符和 ZWJ；这些回退字符不一定与微信图像的含义完全一致。
- 文档 ID 以十进制字符串保存，不能转成 JavaScript `number`，否则会丢精度。

正文、普通/公众号/群聊转发、引用的可见文字、媒体说明、名片说明、合并记录展开、附件重试和 WebUI 同步都走最终 HTML 发送边界。原始归档内容不改写。URL/HTML 属性、链接内容、`code`、`pre` 和已有 `<tg-emoji>` 内不重复转换，避免损坏链接、代码或嵌套实体。单独发送的图片、GIF 和贴纸仍按原来的媒体路径处理。

## 长度与安全边界

- 保留加粗、引用等已有富文本，正文按解析后的 UTF-16 长度分片，每片最多 4096；分片保持标签闭合，不切开自定义表情或代理对。
- 每次渲染保守限制为最多 100 个新建/已有自定义表情实体；超过预算的已匹配表情使用该包准确的普通 Emoji 回退，不丢弃文本。
- 媒体说明最多 1024 的边界处，若回退字符比原生别名更长、转换会让原本合法的说明超长，则保持整段原文，而不是截断内容。
- 关闭模式的短消息保持原来的 HTML。未知或不平衡 HTML 不会被此功能当成通用 HTML 修复器处理。
- Topic、回复目标和旧绑定不改变；General 的防误发规则继续生效。

映射位于 `src/util/WechatCustomEmojiData.ts`；测试用的公开表情包元数据快照位于 `test/fixtures/wechatpack.json`，不包含账号、令牌或真实消息。测试覆盖真实 GramJS 实体解析、长 ID 精度、同 Emoji 不同图像、开关优先级、UTF-16 偏移、长文本和媒体说明边界，以及两种发送接口的路由保持。实际展示效果仍需用具备发送资格的机器人验收。
