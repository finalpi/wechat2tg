# 联系人、微信群和公众号的富文本分页

`/user`、`/room`、`/official` 共用同一套列表界面：HTML 加粗标题、页码、总数、搜索条件与可见条目，下方保留普通文字选择按钮。按钮文字不包含 HTML 或自定义表情标记，联系人原名中的 Emoji 保留。

## 翻页与返回

- 默认每页 30 条，搜索结果也分页，不再一次展开 999 个按钮。正文按 Telegram 的 4096 UTF-16 长度预算压缩过长显示名称，仍保留该页全部 30 条；原始 ID 与完整查询不变。
- 上一页、下一页保留完整搜索条件和当前类别，不会从公众号列表跳到普通联系人列表。
- 「返回首页」回到当前搜索结果第一页；「返回完整列表」清除搜索，展示同一类别的完整列表。
- 选择联系人/群组后的结果消息带有「返回列表」，恢复原搜索条件及页码，不会再次执行建群或绑定操作。
- 列表数据会刷新。如果联系人数量变少，会自动校正页码；没有结果时显示空列表，而不是产生非法页码。
- 搜索字符串按完整内容查询，只有显示部分会截短；HTML 特殊字符会转义。较长名称只截短显示，不改动所选微信 ID。

## 旧按钮与安全边界

每次显示页面都会生成一个独立的短回调标记，保存该页条目的不可变快照。因此即使后台顺序变化，点击旧页上的名字仍指向当时的微信 ID，不会按新列表的相同位置选错联系人。

页面状态限定当前 Telegram 用户、聊天、Topic 和微信账号，默认保留 30 分钟，最多缓存 512 个页面。过期、缓存被淘汰或 bot 重启后，旧的新式按钮会提示重新发送列表命令，不抛出原始异常，也不会猜测目标。旧版 `us/of/ro` 选择按钮保持兼容；旧分页按钮可以刷新所属类别，但旧格式没有携带搜索条件，无法恢复原搜索。

公众号分类仍使用 `VerifyFlag`；未知资料仍独立提示，不当成普通联系人。受管理公众号论坛仍禁止整群重绑，翻页本身不会修改任何绑定。

## 编辑失败时的回退

- 重复编辑导致 Telegram 返回 `message is not modified`：按成功处理，不另发消息。
- Telegram 明确拒绝 HTML 实体：回退成同一份纯文本内容和按钮。
- Telegram 明确说明旧消息已删除或不能编辑：发送一个新的列表，保留原 Topic。
- 回退发送本身失败、回调确认超时等：异常在界面边界处理，不泄漏为未捕获的 Promise 拒绝。
- 网络超时、5xx、429、403 等不确定或不可重试结果：不会盲目另发一条列表，避免重复消息。用户可稍后重试命令。

这些回退仅用于列表交互，不改变普通微信转发、媒体重试或消息投递的现有规则。文件夹、群组和微信服务不会因分页操作被重建。
