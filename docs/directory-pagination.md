# 原生富文本：直接点击姓名选择、点击文字翻页

`/user`、`/room`、`/official` 默认使用 Telegram **原生 RichMessage**，不是把 HTML 名单和下方键盘重复显示。

- 名字本身是正文里的可点击文字，点击即触发选择。
- 「上一页」「下一页」「返回首页」「返回完整列表」「返回列表」同样通过正文中的回调完成操作。
- 不使用 `t.me?...start=` 深链接，不跳转聊天，也不要求重新点击 Start。
- 名称按两列排布，默认每页 30 条；普通 Unicode Emoji 保留，真实微信 ID 不会因显示截短而改变。

实现采用官方 [`sendRichMessage`](https://core.telegram.org/bots/api#sendrichmessage)、[`RichTextButton`](https://core.telegram.org/bots/api#richtextbutton) 和 [`RichMessageButton`](https://core.telegram.org/bots/api#richmessagebutton)。`style: "link"` 的回调按钮可以嵌在富文本段落中，按下后仍产生标准 CallbackQuery。翻页通过 [`editMessageText`](https://core.telegram.org/bots/api#editmessagetext) 的 `rich_message` 参数更新，不同时传入普通 `text`。

## 只读联系人与群成员

- `/contacts [名称或备注]` 列出普通联系人，点击姓名查看详情，不进入绑定或建群流程。
- `/members [群名称或备注]` 列出微信群，点击群名打开群成员，再点击成员查看详情。在已绑定微信群的 Telegram 群组/Topic 内直接发送 `/members`，会使用当前群组/Topic 对应的微信绑定。
- 成员每页 30 人，可返回原群列表的搜索和页码；成员详情的「返回列表」恢复原成员页。
- 成员名单复用现有微信群成员接口与 60 秒缓存；联系人详情只读取本地缓存，展示微信 ID、微信号、昵称、备注、性别、地区、签名和描述中已有的字段。非好友成员没有缓存资料时仅显示 ID 和群内名称，不伪造缺失资料。
- 原生富文本、兼容键盘、账号/用户/聊天/Topic 隔离及过期规则均与原目录相同。`/user`、`/room`、`/official` 的原有绑定行为不变。

## 翻页与返回

- 搜索结果也按每页 30 条展示，上一页、下一页保留完整查询和类别。
- 「返回首页」回到当前查询第一页；「返回完整列表」清除查询，显示同一类别。
- 选择后的结果消息提供「返回列表」，恢复原查询和页码，不重新执行绑定或建群。
- 数据变少时自动校正页码。缺失、无结果、未知分类均有明确提示，不选错别的联系人。
- 完整查询与 ID 保留；显示用长查询和长名称可截短。原生内容采用结构化文本，禁止自动实体检测；名字里的 HTML 标记不会变成可执行排版。

## 兼容模式与失败回退

原生列表下方只保留一个「兼容模式」入口，供不能正常显示 RichMessage 的旧客户端使用，**不再重复一套联系人和导航键盘**。兼容模式只显示简洁标题、页码和查询信息，联系人及导航放在普通键盘中；不会在正文再抄一遍名单。

- Telegram 接口明确表示原生方法或富文本结构不受支持时，才自动回退到兼容模式。
- 兼容模式的 HTML 被明确拒绝时，再回退纯文本，保留相同的选择与导航目标。
- 旧消息明确无法编辑、已被删除时，可以发送新列表；保留原 Topic，不掉到 General。
- `message is not modified` 按成功处理，不另发消息。
- 网络超时、5xx、429、一般性 403 等失败不自动补发，避免结果不确定时产生重复消息。
- 回调确认、编辑或回退发送失败均在界面边界处理，不产生未捕获的 Promise 拒绝。所有自动尝试都有次数上限。

服务端无法知道每个客户端是否能正确显示原生富文本。因此已成功发送但旧客户端无法显示时，请使用「兼容模式」；重新发送列表命令会再次尝试原生模式。

## 状态与安全

每页有独立的短回调标记，关联该页条目的不可变快照。名单顺序改变后，旧名字仍对应当时的微信 ID，不按新列表的相同位置猜测。状态限定当前用户、聊天、Topic 与微信账号，默认 30 分钟、最多 512 页；过期或重启后提示重新查询。

旧版 `us/of/ro` 按钮继续兼容。公众号识别仍按 `VerifyFlag`，受管理论坛仍禁止整群重绑。重叠点击会合并处理，临时失败完成后仍可显式重试。分页和模式切换本身不创建群组、不修改绑定，也不改变普通消息转发的重试策略。
