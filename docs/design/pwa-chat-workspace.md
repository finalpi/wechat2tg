# PWA 与聊天工作区设计草案

状态：用户已同意开始实现。本文保留总体设计，第一阶段实际完成范围及剩余事项见 [PWA 与聊天工作区说明](../pwa-chat.md)。第一阶段进入 `v6.0.40-dev.3` 开发预览，未代用户部署；不把下述所有规划都视为已交付。

将需求中的「WPA」按 PWA（可安装的 Web 应用）理解。目标是接近 Telegram Web 的日常聊天体验，而不是在管理后台里增加一个放大按钮，也不是承诺完整复刻 Telegram 客户端。

## 1. 核心方向：聊天与管理分开

仍然只有一套 React / shadcn WebUI，复用现有消息接口、SSE、附件、引用、撤回与发送幂等机制。

建议两个工作区：

- `/chat`：纯聊天工作区，PWA 默认启动入口。桌面会话列表 + 聊天内容，手机单栏切换。
- `/manage`：现有管理功能，包括连接设置、AI、模板、自动化和 MCP。

第一阶段已增加这些页面路由及严格范围的 SPA 刷新回退；它们不是新增 API，API / 静态资源的真实 404 和鉴权行为保持独立。

聊天工作区不显示管理侧栏、品牌顶栏、配置保存栏、外层 Card 和大面积 padding。管理入口放入会话列表左上角菜单；返回聊天应恢复当前会话、滚动位置和草稿。退出聊天模式不等于退出登录。

聊天入口不再依赖完整配置表单加载。共享登录边界，但聊天数据与管理设置分别初始化；配置页加载失败不能挡住整个聊天界面。

## 2. 三种显示状态

1. **纯聊天模式**：隐藏所有管理界面。桌面仍保留会话列表，是默认状态。
2. **专注当前会话**：收起会话列表，只保留聊天标题、消息流和输入框。明确提供恢复列表入口，刷新后可恢复选择。
3. **浏览器全屏**：可选增强，仅在浏览器支持 Fullscreen API 时提供；不把它作为前两种布局的前提。Escape 可退出浏览器全屏，但不丢失会话状态。

PWA 的独立窗口没有普通浏览器地址栏，但不等于操作系统级全屏。Telegram Mini App 复用纯聊天布局；网页不能保证移除 Telegram 原生顶栏，宿主全屏能力只能检测支持后适配。

## 3. 桌面布局

```text
┌─────────────────────┬─────────────────────────────────────────┐
│ ☰  搜索会话         │ 头像  当前群名           搜索  专注  ⋯ │
│ 最近  联系人  群聊  ├─────────────────────────────────────────┤
├─────────────────────┤                今天                     │
│ 头像 群名      时间 │ 成员名称                                │
│      最新消息摘要   │  对方消息气泡                           │
│                     │                     我的消息气泡        │
│ 头像 联系人    时间 │                     时间 / 发送状态     │
│      最新消息摘要   │                                         │
│                     │               有新消息 ↓                │
│                     ├─────────────────────────────────────────┤
│                     │ 引用 / 附件预览（需要时显示）           │
│                     │ ＋  输入消息…                    发送   │
└─────────────────────┴─────────────────────────────────────────┘
```

- 左栏建议默认约 320px，可拖动调整并记住宽度；窄窗口自动切单栏，不挤出无法使用的双栏。
- 聊天头部仅一行。默认不常驻显示 wxId、多块在线徽章、群成员工具条。
- 点击标题打开群 / 联系人详情。资料和会话搜索作为按需抽屉，不默认占第三栏；首版仅展示已有数据，不摆放无后端支撑的管理按钮。
- 内容区域自适应，消息内容适度限宽，避免在宽屏横跨整行。延续项目靛蓝强调色，浅色 / 深色都用语义色。
- 日期分隔、连续同一发言者分组、群成员名、回复引用和时间状态形成清楚层级；不增加多余边框和卡片套层。

## 4. 手机与 Mini App

手机是两个页面状态，不是缩小的桌面双栏：

```text
会话列表                       当前会话
┌───────────────────┐         ┌───────────────────┐
│ ☰   搜索会话      │         │ ‹  头像 群名   ⋯ │
│ 最近 联系人 群聊  │         ├───────────────────┤
├───────────────────┤         │ 消息              │
│ 头像 群名    时间 │   点击  │       我的消息    │
│      最新消息     │ ──────> │                   │
│ 头像 联系人  时间 │         │                   │
│      最新消息     │         ├───────────────────┤
└───────────────────┘         │ ＋ 输入消息  发送 │
                              └───────────────────┘
```

- 进入会话后只留下聊天头部和输入区，没有第二排系统导航或品牌栏。
- 返回先关闭媒体预览 / 抽屉，再回会话列表；浏览器后退、手机返回和 Telegram BackButton 应遵循一致的层级。
- 键盘弹出后输入框始终可见；采用动态可视区域与 safe-area，不用固定屏幕高度猜键盘位置。
- 输入框按内容增长但有高度上限，不因长草稿挤没消息区域；输入法选字期间 Enter 不能误发送。
- 图标按钮保持适合触摸的命中范围，不靠缩小按钮来节约空间。
- 竖屏普通文本会话中，头部与空输入区尽量控制在约 110～130px，不含系统安全区；最终以真实设备和键盘测试为准。

## 5. 优先做像聊天客户端的交互

### 会话列表

- 头像、名称、末条消息、时间、选中状态；搜索默认面向会话，全文搜索按需进入。
- 保留已有「最近 / 联系人 / 群聊」筛选，不凭 ID 前缀推断公众号分类。
- 未读与 Telegram 待同步必须分开：不能把现有 unsyncedCount 伪装成聊天未读。跨设备未读同步需要专门的阅读位置设计，首版不冒充微信官方未读状态。

### 消息流

- 桌面右键 / 悬浮操作、手机长按，集中提供已有的复制、引用、撤回、同步重试等动作；保留正常文字选择。
- 往上读历史时，新消息不抢滚动位置；显示「有新消息」入口。向上加载历史、引用跳转、SSE 更新不能让列表跳动。
- 切换会话、聊天 / 管理工作区以及专注模式时保留草稿和当前位置。
- 搜索、媒体预览、引用跳转采用按需面板，避免常驻控件占据消息区域。

### 输入区与发送状态

- 附件入口、自动增长的输入框、发送按钮；选文件 / 引用时才增加预览条。
- 复用现有文字、附件拆分发送与 requestId，不能因为换界面破坏幂等重试。
- 发送状态采用后端真实能确认的「发送中 / 已提交 / 失败 / 结果不确定」。不展示虚假的对方已读、输入中或蓝色双勾。
- 首版保留已有 Ctrl / Cmd + Enter 发送习惯；若提供 Enter 发送，做成显式偏好，并覆盖中文输入法测试。

## 6. PWA 设计与边界

### 安装

- 添加 manifest、192 / 512 图标、maskable 图标和 iOS 主屏幕图标。
- 建议 `start_url: /chat`、`scope: /`、`display: standalone`。
- Chrome / Edge 等支持时显示安装入口；iOS 提供 Safari「添加到主屏幕」引导。不支持安装的环境继续正常使用网页。
- 首版沿用现有登录方式；不要把可安装误做成免登录。

### HTTPS

局域网 `http://10.0.0.202:17863` 不能作为可靠的 PWA 安装 / Service Worker 入口。应使用受信任证书的 HTTPS 地址，可优先复用现有 HTTPS 入口。localhost 开发例外不能套用到普通局域网 IP。

Telegram Mini App 内不强行展示安装提示；PWA 安装从普通浏览器完成。

### 缓存与断网

首版保守处理：

- 只缓存公共应用外壳、版本化 JS / CSS 和图标。
- 不默认离线缓存聊天正文、搜索结果、附件或配置；API、SSE、鉴权响应必须绕过 Service Worker 缓存。
- Service Worker 不保存 Token，不接管认证，也不把 Mini App 会话变成持久登录；Mini App 仍只接受 Telegram 签名的主人会话，不回退浏览器 Token。
- 断网显示明确状态，保留当前编辑内容；不自动囤积并重放发送、撤回或接龙操作。
- 应用进入后台后可能被系统挂起，返回前台要恢复 SSE 并补齐消息，不通过定时轮询维持假在线。

### 更新

有新版本时提示「更新可用」，不要聊天中强制刷新。用户确认后再切换 Service Worker；有草稿 / 附件 / 未完成发送时先保护状态或阻止刷新。退出和账号切换要清理账号关联的临时数据。

### 通知

PWA 可安装不等于可以在关闭窗口后持续收消息。可靠后台通知需要独立 Web Push 方案、服务端订阅管理和平台测试；首版不承诺依靠 SSE 实现后台通知。后续若加入，默认锁屏不展示聊天正文。

## 7. 实现顺序

1. **先确认交互稿**：桌面双栏、手机单栏、专注会话三种状态；用合成数据展示，暂不触发真实发送。
2. **聊天工作区**：分离聊天壳层和管理壳层，复用消息模块；优先保证返回、草稿、滚动和发送可靠性。
3. **PWA 安装与更新**：补 HTTPS 场景、manifest、静态缓存、安装引导、安全更新流程和前后台恢复。
4. **体验增强**：按需求加入本地阅读位置、快捷键、自定义背景。Web Push、离线历史、跨设备阅读同步另行评估，不混进第一版。

## 8. 验收重点

- 桌面聊天区没有管理顶栏 / 侧栏 / 外层卡片；模式切换不重复创建消息流连接。
- 320 / 390 / 430px 手机宽度以及桌面宽屏下不横向溢出，长群名和长消息可用。
- 真实手机键盘、中文输入法、安全区、浏览器 / Telegram 返回键可用。
- 切换会话和模式不丢草稿；历史翻页、引用定位、新消息到达不抢滚动位置。
- 发送 / 附件 / 撤回 / 同步重试仍走已验证的服务端流程，不增加重复投递。
- PWA 安装、独立窗口启动、带路由刷新、更新提醒、断网提示及前台恢复均验证。
- 浏览器 Token 与 Mini App 主人签名鉴权仍独立；缓存不泄露受保护数据。

推荐先以「Telegram Web 式双栏 + 移动单栏 + 按需专注」作为主方案，而不是继续在管理后台中堆叠聊天工具栏。
