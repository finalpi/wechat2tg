# 聊天文件夹满额后的处理

文件夹只是 Telegram 会话的整理方式，不是建群、绑定或消息转发的前置条件。

## 分配规则

1. 新建的普通联系人群、微信群绑定群优先放入 `WeChat`。
2. 当前文件夹满额时，优先使用已有且还有空间的 `WeChat 2`、`WeChat 3` 等，按数字顺序选择。
3. 已有文件夹都满了，会尝试创建下一个未使用的名称。不会重命名、重排或删除现有文件夹。
4. 账号的文件夹总数也达到上限时，停止整理：**群仍然创建成功，绑定保留，消息继续转发**。在 Telegram「全部聊天」中仍可找到该群。
5. 公众号论坛验证就绪后也会尝试加入文件夹；一个论坛只占一个会话名额，不论里面有多少 Topic。文件夹整理失败不会阻止论坛就绪或重新创建论坛。

Telegram 创建群组本身的权限、账号风控和群组数量限制仍然适用；本功能只将文件夹失败降级，不能绕过平台限制。

## 容量与设置保护

- 使用 Telegram 的 [`help.getAppConfig`](https://core.telegram.org/api/config) 配置：`dialog_filters_chats_limit_default/premium`、`dialog_filters_limit_default/premium`，并根据实际登录用户的 Premium 状态选择。
- 常见每文件夹容量为普通账号 100 个会话、Premium 200 个；以服务端返回值为准。账号限额缓存五分钟。
- 读取限额失败时，按保守的 100 个会话分配；不猜测文件夹总数，让 Telegram 明确拒绝后正常跳过。
- 已有手动加入及置顶的会话也计入容量，相同会话只计一次。例如首个文件夹里的机器人也占一个会话名额，并不是必然可以再放满 100 个群。
- 不修改共享文件夹，其他名称的文件夹保持原样；但它们仍占账号的文件夹总额度。这里只管理精确名称 `WeChat` 和 `WeChat N`（N 为至少 2 的正常十进制整数）。
- 更新已有文件夹时保留原来的图标、过滤条件、置顶、排除列表及手动添加的会话。如果目标会话被明确排除，不会绕过排除设置再塞进其他文件夹。
- 不需要新增 `.env` 参数，不修改数据库 schema；不批量迁移或重建历史群组。

## 失败与并发

同一 Telegram 用户客户端共享一个文件夹操作队列，避免多个新群同时读写旧列表、丢失成员或创建重名文件夹。成员去重按实际用户／普通群／超级群的标记 ID 区分，不依赖对象引用或只比较 `chatId`。

群组先创建并保存绑定，文件夹整理在后台执行。文件夹满额不是建群错误，也不会弹出“建群失败”；日志可记录已跳过整理。获取文件夹、解析会话和更新文件夹的异常都在整理边界处理，不产生未捕获的 Promise 拒绝。

只有明确的单文件夹容量错误才尝试下一份文件夹。遇到限流、连接失败或结果不确定的请求，不盲目重试或连续创建其他文件夹。已经创建的群继续可用，后续正常分配会重新读取服务端状态。

测试使用真实 GramJS 请求序列化和模拟服务端状态，覆盖 99→100→新文件夹、Premium 配额、总数耗尽、共享文件夹、并发追加、原设置保留、异常恢复及建群/论坛不受整理失败影响，不会为了测试在线创建大量群或文件夹。
