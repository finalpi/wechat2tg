# 聊天界面与显示偏好

入口：聊天菜单 → 管理设置 → 聊天界面。

- 在通讯录预览中点击眼睛，隐藏或恢复群聊、公众号、服务号、企业微信联系人、联系人、待识别分类。
- 偏好即时生效于聊天列表和通讯录，保存在当前浏览器的 `webui-chat-preferences-v1` 中；不跨设备同步，不修改实例的转发规则，不删除任何消息或联系人。
- 「显示全部分类」恢复默认显示。隐藏正在打开的会话会返回列表，但保留其未发送草稿。拖动排序尚未实现。
- 鼠标悬停消息或键盘聚焦操作时显示回复、同步、撤回等工具；触屏通过每条消息旁的省略号打开。同步提示与操作位于消息正文之后的页脚，占用正常布局空间，不以浮层遮挡原消息；桌面预留空间，悬停不挤动阅读位置。发送失败、结果未知和撤回结果仍会直接提示，不隐藏重要错误。
- 连接状态默认仅显示 emoji；点击可查看微信、Telegram 和消息连接详情。未接入的「新的朋友」「我的企业」不再占用通讯录空间。

## 刷新联系人列表

聊天 / 通讯录标题旁的刷新按钮会重新请求服务端当前账号的缓存目录，而不只是重绘界面：

- 刷新中显示转圈和进度提示，禁止重复点击；保留当前搜索、分类以及已加载的分页。
- 绕过浏览器缓存，重新获取整个已加载窗口及各分类数量；全部成功后一起替换，不先清空旧列表。折叠所有分类时仍会刷新数量。
- 清除其他分类的页面缓存，成功后也清除页面内的头像缓存，使可见头像重新请求。普通消息不会因此触发通讯录全量刷新。
- 成功提示「已重新读取服务端缓存」及完成时间，5 秒后收起；失败或超过 30 秒时明确报错、保留原列表，并允许重试。切换分类 / 搜索会取消旧请求，迟到响应不能覆盖新列表。
- **这不是微信全量同步按钮**：当前 SDK 没有公开的主动全量通讯录同步入口。尚未同步到服务端的联系人不会凭空出现，不将读取缓存成功当作微信同步完成。

## 头像

群消息中的每位发言人（含自己）、成员选择器都显示头像。优先使用联系人缓存；非好友的头像可以从所属群的成员资料中取得。缺失或加载失败时显示名字首字占位，不伪造头像。

Web 头像仍经鉴权接口获取，仅允许微信头像 CDN；同一页面中的重复头像请求合并，退出/更换登录会话或手动刷新列表成功时释放缓存，不将头像写入浏览器持久存储。

Telegram `/members` 的分页只显示可点击姓名，不展示头像图集，也不下载整页头像。点击某人后，其详情才显示「小头像 + 姓名」和资料，返回时恢复原成员页。`/contacts` 详情也支持同样的小头像。

Telegram 原生图片块不提供 CSS 尺寸，因此头像缩为 48×48，放在 512×88 的短横条中，旁边直接写姓名；适配消息宽度后仍是小头像，不再放大整张方形头像。完整姓名同时保留在资料 / 图片说明中。仅下载已选择用户的合法微信头像 CDN 图片，经验证后上传缩略图，不把原头像 URL 直接发给客户端。头像缺失时仍展示资料，明确的富文本不支持或头像拒绝响应会退回文字详情与返回按钮；网络超时等结果不明的错误不会自动重复发送。真实显示效果取决于 Telegram 客户端及 Bot API 的富文本支持。

## 验证

- `npm test`：后端、分页、鉴权、头像来源与文字回退回归测试。
- `npm run test:webui:browser`：包含悬停/键盘/触屏操作、成员头像请求复用、可视化隐藏/恢复及刷新持久化测试；联系人刷新覆盖真实 HTTP 请求、数量 / 已加载分页更新、失败保留旧数据、重复点击、超时和过期响应隔离。
- 浏览器测试使用合成联系人和图片，不发送真实微信或 Telegram 消息。
