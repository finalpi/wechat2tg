# 聊天界面与显示偏好

入口：聊天菜单 → 管理设置 → 聊天界面。

- 在通讯录预览中点击眼睛，隐藏或恢复群聊、公众号、服务号、企业微信联系人、联系人、待识别分类。
- 偏好即时生效于聊天列表和通讯录，保存在当前浏览器的 `webui-chat-preferences-v1` 中；不跨设备同步，不修改实例的转发规则，不删除任何消息或联系人。
- 「显示全部分类」恢复默认显示。隐藏正在打开的会话会返回列表，但保留其未发送草稿。拖动排序尚未实现。
- 普通聊天悬停 / 键盘聚焦时显示省略号，点击后展开回复、同步、撤回等工具；触屏也使用省略号。公众号卡片保留原来的悬停工具。展开的操作位于正文之后的正常布局中，不盖住内容；悬停本身不改变高度。发送失败、结果未知和撤回结果直接显示，不隐藏重要错误。
- 连接状态默认仅显示 emoji；点击可查看微信、Telegram 和消息连接详情。未接入的「新的朋友」「我的企业」不再占用通讯录空间。

## 聊天输入

- 群聊直接输入 `@` 即可弹出成员候选，继续输入昵称或微信 ID 筛选；支持键盘选择和触屏点选。
- 输入框左侧不再单独显示 `@` 成员按钮，避免重复入口；附件和微信表情选择按钮保留。

## 消息卡片

- 所有消息共用 `ChatMessageCard`。普通聊天使用 shadcn `MessageGroup` / `Message` / `Bubble` 的紧凑气泡；公众号 / 服务号仍使用完整的 Card Header / Content / Footer，不改变图文封面布局。
- 群聊昵称使用 13px 半粗主色，正文 15px 正常字重，时间为 10px 弱化色、24 小时格式，形成明确层级。自己发的消息没有昵称和头像；单聊收到的消息不重复显示会话名字。
- 同一会话、同一真实发送者、同一方向、同一天且在列表中连续的普通消息合为一组，不再因间隔超过 5 分钟而重复显示头像。例如 18:09 和 19:03 之间没有其他人的消息时共用一组，仍各自显示真实时间。不按相同昵称或正文合并，不删除重复文字；未知成员身份、系统 / 撤回提示、跨天或换人仍另起一组。
- 每个接收消息组仅有一个外侧头像，群昵称仅在组首显示；CSS sticky 让头像在视口下沿跟随长消息组，并被严格限制在该发送者的组内。消息仍各自保留时间、引用、同步、撤回与定位 ID。
- 组内气泡间距为 4px，连接侧转为小圆角；组间 / 公众号卡片间距手机 16px、桌面 20px。普通聊天保留左右方向与发送色调，长正文保持换行。
- 文字、图文链接、附件、引用与撤回状态沿用同一容器。公众号 / 服务号图文支持消息自带的封面，行为与安全边界见下文。
- `MessageScroller` 继续负责跟随、历史加载和定位；组容器及组内消息分别注册，引用可以定位到组内准确消息。加载旧消息合并到同发送者组时，通过 scroller 的定位 API 恢复原可见消息位置，不因分组合并跳动。浅色、深色与手机布局使用语义颜色。

## 公众号 / 服务号图文封面

- 从原始图文消息的 `cover`、`coverurl`、`thumburl`、`thumb_url` 或 `picurl` 中提取封面。旧缓存会重新解析一次补齐字段；不抓取文章网页、不猜测封面、不伪造阅读量 / 点赞数。
- Web 使用 shadcn 图文卡片：首篇大封面与标题，后续文章为标题摘要 + 右侧缩略图；标题和封面均可打开原文，不重复展示旧的文本版图文列表。无封面 / 下载失败时保留可读标题和链接。
- 封面经鉴权的 `/api/media/article/<消息ID>/<索引>` 提供，浏览器不直接访问 CDN、不把 Token 放入 URL、不接受客户端传入远程 URL。图片接近可见区域后才加载；撤回、隐藏或账号切换时不继续返回旧消息封面。
- 只下载 `mmbiz.qpic.cn` / `mmbiz.qlogo.cn`，旧 HTTP 链接升级为 HTTPS，每次重定向重新校验；最多 3 个并发、32 个待处理请求、3 MiB 输入、800 万像素和 8 秒网络截止时间。图片重新编码为 JPEG，私有磁盘缓存最多 128 张、24 小时，失败短暂缓存以避免重复请求。
- Bot 转发使用一个原生 Telegram 富文本消息，首篇大封面，其余封面组合为图文拼贴，保留原文链接与摘要。Telegram 决定具体布局，无法完全复刻微信右侧小图排版；每条最多附带 10 张封面，其他文章仍有文字链接。原文最多解析 20 篇。
- 图文走媒体通道，不让封面上传占住普通文字通道。仅在明确的原生格式 / 图片拒绝时退回文本；429、超时、连接重置不额外补发一条文本。文本回退已经形成持久分片记录后，重试不会突然改发整条图文造成重复。
- 演示模式使用本地生成的示例封面，不访问外部图片服务。旧的 Telegram 消息不会被批量编辑或重发，实际客户端图文样式仍需验收。

## 刷新联系人列表

聊天 / 通讯录标题旁的刷新按钮会重新请求服务端当前账号的缓存目录，而不只是重绘界面：

- 刷新中显示转圈和进度提示，禁止重复点击；保留当前搜索、分类以及已加载的分页。
- 绕过浏览器缓存，重新获取整个已加载窗口及各分类数量；全部成功后一起替换，不先清空旧列表。折叠所有分类时仍会刷新数量。
- 清除其他分类的页面缓存，成功后也清除页面内的头像缓存，使可见头像重新请求。普通消息不会因此触发通讯录全量刷新。
- 成功提示「已重新读取服务端缓存」及完成时间，5 秒后收起；失败或超过 30 秒时明确报错、保留原列表，并允许重试。切换分类 / 搜索会取消旧请求，迟到响应不能覆盖新列表。
- **这不是微信全量同步按钮**：当前 SDK 没有公开的主动全量通讯录同步入口。尚未同步到服务端的联系人不会凭空出现，不将读取缓存成功当作微信同步完成。

## 头像

群聊收到的连续同人消息在气泡组外侧仅显示一个跟随滚动的头像；自己发的消息不显示头像。成员选择器仍显示成员头像。优先使用联系人缓存；非好友的头像可以从所属群的成员资料中取得。缺失或加载失败时显示名字首字占位，不伪造头像。

Web 头像仍经鉴权接口获取，仅允许微信头像 CDN；同一页面中的重复头像请求合并，退出/更换登录会话或手动刷新列表成功时释放缓存，不将头像写入浏览器持久存储。

Telegram `/members` 的分页只显示可点击姓名，不展示头像图集，也不下载整页头像。`/members` 与 `/contacts` 的个人详情只显示已有资料字段和返回入口，不再展示「资料来自本地缓存，未提供的字段不显示」等实现说明。

头像放在默认收起的「头像」项中，展开后显示一张 256×256 的圆形裁切图片（白色底），不再使用姓名横幅、不重复显示姓名。Telegram Bot API 的图片块不能指定聊天列表式的小头像尺寸，展开后的大小和样式仍由客户端决定；旧横条在实际客户端会被拉宽，已弃用，不承诺能复刻 Telegram 原生聊天头像。

仅下载已选择用户的合法微信头像 CDN 图片，经验证后上传，不把原头像 URL 直接发给客户端。收起只影响显示，图片仍随详情消息上传；头像缺失时不显示空的头像项。明确的富文本不支持或图片拒绝响应会退回文字详情与返回按钮；网络超时等结果不明的错误不会自动重复发送。实际折叠和图片显示效果仍需 Telegram 客户端验收。

## 验证

- `npm test`：后端、分页、鉴权、头像来源与文字回退回归测试。
- `npm run test:webui:browser`：包含悬停/键盘/触屏操作、成员头像请求复用、可视化隐藏/恢复及刷新持久化测试；联系人刷新覆盖真实 HTTP 请求、数量 / 已加载分页更新、失败保留旧数据、重复点击、超时和过期响应隔离。
- 浏览器测试使用合成联系人和图片，不发送真实微信或 Telegram 消息。
