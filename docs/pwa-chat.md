# PWA 与独立聊天工作区（v6.0.40-dev.3 开发预览）

这是 [设计草案](design/pwa-chat-workspace.md) 的第一阶段实现，从 `v6.0.40-dev.3` 提供开发预览。镜像以对应 Actions 构建成功为准，不是稳定版，不自动部署。

## 入口与布局

- `/`、`/chat` 默认进入纯聊天工作区；`/manage` 打开管理设置。均可直接刷新，不是新增 API。
- 聊天页面没有管理顶栏、管理侧栏或外层卡片。左上角「聊天菜单」进入管理设置、切换主题、安装应用或退出登录。
- 桌面默认双栏，会话侧栏宽度可拖动调整（260～440px）；分隔条可用左右方向键、Home / End 调整。宽度只保存为本地界面偏好。
- 聊天头部「专注当前会话」收起侧栏，「显示会话列表」恢复。该偏好与浏览器全屏独立。
- 手机采用列表 / 会话单栏。应用内返回、浏览器后退 / 前进与 Telegram BackButton 支持回到会话列表；草稿保存在当前登录会话的内存中。
- 支持 Fullscreen API 的普通浏览器，在聊天菜单提供浏览器全屏；不保证 Telegram 原生顶栏或 iOS 系统栏可以隐藏。
- 切换聊天 / 管理工作区保留当前会话、草稿和阅读位置，保持同一个 SSE 连接。聊天初始化不请求整份 `/api/config`，配置页不再成为打开聊天的前置依赖。
- 移动输入字体与单行输入区适配软键盘；输入区自动增长且有上限。保留 Ctrl / Cmd + Enter 发送，输入法合成期间不触发发送。

## PWA 安装

在普通浏览器里通过受信任 HTTPS 地址访问。Chrome / Edge 支持时可在聊天菜单点「安装应用」；未出现系统安装提示时使用浏览器自己的安装菜单。iPhone / iPad 使用 Safari 的分享 → 添加到主屏幕。

普通局域网 HTTP 地址（例如 `http://10.0.0.202:17863`）不具备完整的 PWA 安全上下文；localhost / 127.0.0.1 仅是开发例外。不要为安装而关闭证书校验。可沿用现有的 HTTPS WebUI 域名，无需新增账号系统。

应用使用 `manifest.webmanifest`，`start_url=/chat`、`scope=/`、`display=standalone`，提供普通、maskable 和 iOS 图标。Telegram Mini App 不注册 PWA worker、不显示安装操作；继续使用主人签名会话，不回退保存的浏览器 Token。

## 缓存与更新安全

构建脚本从公共应用外壳与打包资源内容生成 `/sw.js`，不是手写版本号：

- 仅预缓存公共 HTML、manifest、图标和构建生成的带 hash 资源。预缓存请求不带凭据。
- API、SSE、认证响应、MCP、媒体 / 附件、下载表情、带 Authorization / Range 的请求、非 GET、跨源与带 query 的 URL 不进入缓存。
- 不缓存 Token、联系人或聊天内容；没有离线聊天数据库、后台发送队列或自动重放操作。已打开的会话断网后仍可编辑内存草稿，但发送禁用，恢复网络也不会自动发送。
- 断网时仅 `/`、`/chat`、`/manage` 能回退到公共应用外壳；未知路径、API 404 和带 query 的导航不作离线回退。
- 更新不会自动 skipWaiting 或强制刷新任何窗口。新 worker 就绪后显示提示；用户确认更新才请求激活。
- 聊天草稿、引用、附件、发送 / 重试中的操作、配置以及函数 / 规则 / MCP 编辑保护会阻止更新刷新。激活完成后再次检查，避免等待期间新写的草稿丢失；被阻止时保留更新入口，完成编辑后可再次确认刷新。
- 只有主动批准更新的窗口刷新，其他窗口不刷新；缓存保留当前及上一代已激活的公共资源。
- 浏览器 / PWA 退出或更换保存的 Token 时，其他打开的浏览器窗口会清空旧登录状态及内存会话。Mini App 的签名会话不与浏览器 Token 联动。

PWA 安装不等于后台常驻。应用被系统挂起后，回到前台通过现有 SSE 和按事件触发的状态 / 消息补齐恢复，不新增定时 HTTP 轮询。关闭窗口后的后台通知需要另做 Web Push，本阶段未实现。

## 使用与开发

```sh
npm run dev:webui
```

使用启动器打印的本地地址与 Token。聊天入口为 `/chat`，管理入口为 `/manage`；不要将真实 Token 放进 URL。此开发入口不是让另一套 Bot 同时登录真实账号。

```sh
npm run build
node --test --test-concurrency=1 test/*.test.cjs
npm run test:webui:browser
```

`test:webui:browser` 包括消息、配置、Mini App、自动化和新增 PWA / 聊天工作区五组浏览器测试。新增测试使用真实 Chromium service worker 和 HTTP、临时目录及合成消息，不操作真实账号。

覆盖：

- 聊天独立于配置加载、双栏 / 专注切换、侧栏调整、浏览器返回、草稿及滚动保留、单一 SSE。
- 移动可视区域缩小时输入框可见、长草稿限高；这不代替真实 iPhone / Android 软键盘验收。
- 真实 worker 安装、静态缓存、等待更新、有草稿时阻止刷新、批准窗口更新、其他窗口草稿保留。
- 缓存中无测试 Token / 私有消息；断网仍能加载外壳，但受保护 API 不从缓存成功返回；多窗口退出清理。
- 原有发送、附件、引用、撤回、幂等重试、配置冲突、自动化安全边界和 Mini App 主人鉴权回归。

## 当前边界

首版优先完成可安装、纯聊天布局与可靠状态保留。聊天草稿仅保存在当前登录窗口内存，不承诺关闭应用后的草稿恢复；更新被阻止时，应先发送、保存或明确清空草稿，而不是强制刷新。

右键 / 长按消息菜单、群资料侧栏、跨设备未读同步、后台推送、离线聊天历史等后续再做；现有引用、撤回和同步按钮仍可使用。不显示虚假的对方已读或输入中状态，也不把 Telegram 待同步数量伪装成未读。

真实安装体验仍需在用户的 HTTPS 入口及实际 Safari / Chrome / Telegram WebView 上验收。本次未修改域名、反向代理、服务端协议、SDK 版本或远端部署。
