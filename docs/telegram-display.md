# Telegram 展示策略与兼容模式

一套消息内容与路由，分别渲染为兼容版或增强版；不复制联系人业务、分页状态、消息发送队列或撤回逻辑。设置只影响后续发送 / 主动翻页等展示，不自动重发历史消息。

## 三种模式

| 模式 | 行为 |
| --- | --- |
| `auto`（默认） | 主人会员状态未知或非会员时使用兼容展示；有近期 Premium 信息时允许增强布局。原生自定义表情还需开启 `WECHAT_CUSTOM_EMOJI_ENABLED`。 |
| `compatible` | 普通文字 / HTML、常规按钮；不发送原生富消息或自定义表情。微信 emoji 默认保留为图片超链接。 |
| `enhanced` | 主动启用增强布局；允许已开启的原生自定义表情，也适用于符合 Fragment 授权而非 Premium 的机器人。明确被 Telegram 拒绝时降级；不绕过权限。 |

`auto` 是保守的产品展示策略，不是“所有 rich API 都要求会员”的断言。**发送资格、已绑定主人的会员状态、接收客户端的兼容性，是三件不同的事。** 普通接收者不必为 Premium；旧版或第三方客户端也不会因为主人是会员就自动兼容。

## 设置方式

机器人主人可以在私聊或目标群发送：

```text
/display                         查看当前模式与会员状态
/display compatible              当前聊天使用兼容版
/display enhanced                当前聊天主动启用增强版
/display auto                    当前聊天自动选择
/display inherit                 当前聊天恢复继承全局设置
/display global compatible       所有未覆盖的聊天默认兼容
/display global auto             全局自动模式
/display global inherit          清除全局覆盖，恢复环境配置
```

覆盖按 Telegram chat ID 生效，同一个论坛的所有 Topic 共用展示模式；Topic 的消息路由不变。只有已绑定主人可以查看或修改，其他用户不能借群聊命令改变模式。控制命令始终用普通文字回复，以免兼容开关本身无法显示。

全局环境默认值也可以通过 WebUI「消息转发」保存，修改环境配置后重启：

```dotenv
TELEGRAM_DISPLAY_MODE=auto
TELEGRAM_EMOJI_FALLBACK=links
WECHAT_CUSTOM_EMOJI_ENABLED=true
```

优先级：当前聊天 `/display` 覆盖 → `/display global` 覆盖 → 环境 / WebUI 默认值。

即时覆盖保存在 `storage/telegram-display.json`，文件权限 0600，写入临时文件后原子替换，保存失败不改变内存设置。按 Bot ID 和主人 ID 隔离；换 Bot / 主人不会套用旧设置。请把它和其他 `storage` 数据一起备份。损坏的同范围配置按兼容模式处理，不静默开启增强功能。

## 主人会员信息从哪里来

- 只接受已绑定主人发来的 `User.is_premium` 信息，忽略其他群成员与机器人。
- 若已有用户 MTProto 会话，登录后读取该账号的 `getMe()` 结果；只有 ID 与已绑定主人匹配才采纳 `premium`。不新增另一套登录流程，不换发送身份。
- 信息只在内存缓存 24 小时，不把旧会员状态写入持久配置。重启或过期后，在没有新的可靠信息前使用兼容展示；主人发送 `/display` 可刷新其 update 中的会员信息。
- Bot API 的 `getMe` 返回机器人本身，不用于检测人类主人的 Premium。项目绑定的主人也不一定是 BotFather 实际创建者，最终功能权限仍以 Telegram 明确响应为准。
- Bot API 不提供阅读消息者的客户端版本。因此没有“已检测所有客户端兼容”的承诺；有旧客户端时选择 `compatible`。

## 各内容的降级

- **微信表情**：原生 `<tg-emoji>` 与普通 HTML 图片超链接共用映射。链接指向原有公开 `finalpi/wechat-emoji` WebP 图片，保留 `[微笑]` / `[Smile]` 等标签；未知编码、普通 Unicode emoji、已有链接和代码不被破坏。设 `TELEGRAM_EMOJI_FALLBACK=text` 可只保留文字；旧 `emojiPicture` 已生成的链接保持原样。详见 [表情映射](wechat-custom-emoji.md)。
- **联系人 / 成员目录**：增强版使用已有富文本按钮；兼容版使用相同数据的 HTML / 普通文字及常规键盘。分页、查询、身份校验、返回和绑定操作共用。已有“兼容显示”按钮仍可用。
- **个人资料**：增强版保留折叠头像；兼容版保留文字字段与返回按钮，不额外发送头像相册。
- **公众号文章**：增强版保留图文封面 / collage；兼容版使用完整标题、摘要和链接的普通文本路径。长内容依旧分片，不为保留图片而把正文截成 1024 字符 caption。
- **红包**：恢复“🧧 收到红包，请在微信客户端查看。”。当前 SDK 的 `red_packet` 以及旧协议 `unknown` + 精确提示“收到红包，请在手机上查看”均可提醒；普通聊天里提到红包不重分类。不打开领取链接、不解析领取凭据、不猜金额或领取状态。

历史检查：`c982ec4` 曾为旧协议红包提示提供转发；后续旧分支有空的 RedEnvelope case。当前版本原先只有 `red_packet` 的通用 `[红包]` 标签，而 unknown 提示可能被过滤。本次恢复的是明确提醒，不是自动抢红包功能。

## 失败与发送安全

- 原生表情只对明确的自定义表情权限 / 格式拒绝降级一次；富消息继续沿用已有明确不支持 / 格式拒绝的降级路径。
- 已确认的拒绝按功能及聊天缓存 6 小时，避免每条消息都先失败一次。不把一条图片下载失败当作自定义表情权限变化。
- 超时、连接重置、一般 403、429、5xx 不触发另一种格式补发。发送结果未知仍由现有持久队列记录，不标成成功。
- 外层文字 / 图片发送已超时或取消后，不再发起迟到的降级请求。
- 兼容模式不改变微信账号、Telegram 发送身份、chat ID、Topic、回复目标、确认后的消息回执或分片检查点。

本地测试使用合成更新和 API 替身，不连接真实账号。真实 Telegram 客户端的增强布局仍需实际验收。
