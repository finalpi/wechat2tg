# 红包封面与手动打开

## 展示

WebUI / Mini App 的红包消息显示祝福语和可用封面。Telegram 新转发及手动同步使用同一份解析结果：原有照片封面 + 既有消息模板中的祝福语 + 一个「拆红包」按钮，不再追加操作说明；无需 Premium 或富消息支持。没有封面、下载失败或 caption 超限时保留文字及按钮。旧的 Telegram 消息不会自动批量重发。

仅从保存的 `appmsg.type=2001` 消息读取图片字段。待拆封面优先使用 `recshowsourceurl`，缺失时回退到通用图标；`detailshowsourceurl` 是拆开后的详情图，发送侧 / 接收侧的 `*c2cshowsourceurl` 是聊天气泡横幅，两者都不能代替待拆封面。图片只允许 `wx.gtimg.com`、`snssvppicb.video.qq.com`、`snssvppicc.video.qq.com`；跳转后重新验证域名，限制下载时间、大小、并发及解码像素，重新编码为 JPEG。浏览器使用鉴权的本地图片接口，不获得原始资源 URL、支付链接或领取凭据。普通公众号封面白名单不扩大。

封面显示和状态读取均不会调用微信领取接口。

`dev.15` 的照片发送器遗漏了按钮参数，导致带封面的 Telegram 红包只显示图片、没有操作入口。修复覆盖 Bot API / MTProto 的媒体发送及 caption 降级编辑，按钮、Topic 和原消息回复关系一同保留；用本机模拟 Bot API 验证真正序列化的 multipart 请求，不只检查上层发送选项。旧的已发送图片不会自动补按钮，也不会因为更新而重新领取。

## 打开与确认

- **Telegram**：只有已配置的机器人主人可以操作。点击原红包下方的「拆红包」即明确同意领取，不再另发二次确认消息。点击后仅应答回调，后台等待和领取期间不编辑消息、不发进度提示，结果出来后至多编辑一次原消息的按钮。照片、文字说明、格式及其他操作按钮保留，不另发结果消息。最终编辑失败也不立即重试或补发；再次查看结果仅通过回调弹窗反馈，不重复编辑。按钮与当前微信账号、主人、绑定会话和 Topic 绑定；转发按钮到别处不能领取。
- **TG 随机等待**：每次明确点击后，先持久记录 `opening`，再随机等待 1～3 秒，等待后重新核对账号、主人、会话绑定和同意时效才派发。重复点击不新增定时任务，跨入口并发仍只派发一次。网络耗时不包含在这段等待中；随机延迟不保证规避风控。等待期间进程重启保持未知状态，不自动补领。
- **WebUI / Mini App**：使用现有主人鉴权。点击「打开红包」先读取状态，尚未处理时弹出确认对话框；确认才提交领取。浏览器管理员 Token 等同管理员权限，必须妥善保管。
- 领取目标只能来自服务端保存的原始红包消息；接口不接受客户端指定的 XML、账号、金额、支付 URL 或领取 ID。旧记录缺少当前账号身份依据、原始载荷不完整、已撤回 / 隐藏、账号切换或微信离线时拒绝领取。
- 「打开」意味着尝试领取到当前微信账号，不只是看一眼封面。不能用它发红包、转账或付款，也不提供自动抢红包、MCP / 自动化领取能力。

旧消息的「拆红包 / 打开红包」按钮也可原位处理；旧的「查看结果」始终只读，不因状态可领取就自动领取。已经发出的旧确认 / 取消按钮仍兼容，但不会再创建额外消息；已存在的历史确认消息不批量删除。

## 结果与防重复

独立私有文件 `storage/db/red-packets.db` 记录操作状态，权限 0600、WAL 和同步落盘。所有入口按「微信账号 + 原生红包 ID」共用同一个操作，发出请求前先原子记录 `opening`。并发点击、不同消息副本和进程重启都不能重复派发。

- `ready`：尚未派发，可重新明确确认。
- `opening`：正在处理，不再派发第二次。
- `received`：外层成功且内层结果包含匹配的红包 ID、有效领取回执和正整数金额，才确认领取成功。金额来自回执，不从封面或通知文字推断。
- `unavailable`：协议路由不支持或微信明确拒绝；在微信客户端查看。
- `unknown`：超时、网络错误、5xx、异常响应或成功响应不足以证明领取。**不得自动重试，也不会切换另一个接口补发。** 重启时遗留的 `opening` 变为 `unknown`。

原始支付 XML 只保存在私有存储中，尝试结束后从领取日志清除；已确认 / 未知状态的去重记录保留。已有消息归档不改写。Telegram 原按钮直接显示「已领取 ¥1.23」，不需要再点“查看结果”；失败显示「领取失败」或「结果未知 · 请在微信核实」。只有日志确认尚未派发、账号及绑定仍有效的失败，才显示「领取失败 · 重试」，再次点击才尝试。已经派发但回执不确定的操作不提供重领按钮。**按钮中的领取金额对所有能看到该消息的人可见**，不再仅限主人弹窗；只有主人能执行领取操作。WebUI 通过鉴权状态接口显示。刷新状态只读取本地日志，不会再次访问领取接口，也不能替代微信端核实未知结果。

## 协议兼容与验证边界

当前协议源码真正注册的组合领取路由为 `/api/TenPay/AutoHongBao`（SDK 基础地址已含 `/api` 时使用相对 `/TenPay/AutoHongBao`）。SDK / Swagger 中旧的 `OpenHongBao` 名称与注册表不一致，因此使用专用、限时且不跟随重定向的请求，而不调用旧 SDK 包装器。HTTP 404 / 405 明确提示路由不可用，不尝试另一个可能再次领取的接口。

Go 实现可能在 JSON 解析失败时仍返回外层成功、内层零值对象，因此不能仅根据 `Code=0` / `Success=true` 显示成功。当前实现严格要求实际回执，宁可显示未知。

自动化测试使用合成 XML、模拟微信响应、临时 SQLite 和本机 HTTP / 浏览器，**不打开任何真实红包**。尚未以真实账户验证协议端领取是否成功；实际行为还取决于当前服务端版本及微信风控。演示模式禁用领取，发布 / 更新代码本身也不会触发领取。
