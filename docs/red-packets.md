# 红包封面与手动打开

## 展示

WebUI / Mini App 的红包消息显示祝福语和可用封面。Telegram 新转发及手动同步使用同一份解析结果：普通照片封面 + 既有消息模板 +「打开红包」按钮；无需 Premium 或富消息支持。没有封面、下载失败或 caption 超限时保留文字及按钮。旧的 Telegram 消息不会自动批量重发。

仅从保存的 `appmsg.type=2001` 消息读取封面字段，区分发送侧 / 接收侧图片，并回退到通用图标。图片只允许 `wx.gtimg.com`、`snssvppicb.video.qq.com`、`snssvppicc.video.qq.com`；跳转后重新验证域名，限制下载时间、大小、并发及解码像素，重新编码为 JPEG。浏览器使用鉴权的本地图片接口，不获得原始资源 URL、支付链接或领取凭据。普通公众号封面白名单不扩大。

封面显示和状态读取均不会调用微信领取接口。

## 打开与确认

- **Telegram**：只有已配置的机器人主人可以操作。点击原红包 → 确认提示 →「确认打开并领取」。取消不会领取，确认有效期两分钟。按钮与当前微信账号、主人、绑定会话和 Topic 绑定；转发按钮到别处不能领取。
- **WebUI / Mini App**：使用现有主人鉴权。点击「打开红包」先读取状态，尚未处理时弹出确认对话框；确认才提交领取。浏览器管理员 Token 等同管理员权限，必须妥善保管。
- 领取目标只能来自服务端保存的原始红包消息；接口不接受客户端指定的 XML、账号、金额、支付 URL 或领取 ID。旧记录缺少当前账号身份依据、原始载荷不完整、已撤回 / 隐藏、账号切换或微信离线时拒绝领取。
- 「打开」意味着尝试领取到当前微信账号，不只是看一眼封面。不能用它发红包、转账或付款，也不提供自动抢红包、MCP / 自动化领取能力。

## 结果与防重复

独立私有文件 `storage/db/red-packets.db` 记录操作状态，权限 0600、WAL 和同步落盘。所有入口按「微信账号 + 原生红包 ID」共用同一个操作，发出请求前先原子记录 `opening`。并发点击、不同消息副本和进程重启都不能重复派发。

- `ready`：尚未派发，可重新明确确认。
- `opening`：正在处理，不再派发第二次。
- `received`：外层成功且内层结果包含匹配的红包 ID、有效领取回执和正整数金额，才确认领取成功。金额来自回执，不从封面或通知文字推断。
- `unavailable`：协议路由不支持或微信明确拒绝；在微信客户端查看。
- `unknown`：超时、网络错误、5xx、异常响应或成功响应不足以证明领取。**不得自动重试，也不会切换另一个接口补发。** 重启时遗留的 `opening` 变为 `unknown`。

原始支付 XML 只保存在私有存储中，尝试结束后从领取日志清除；已确认 / 未知状态的去重记录保留。已有消息归档不改写。Telegram 群内只显示通用处理状态，金额通过仅主人可见的回调弹窗查看；WebUI 通过鉴权状态接口显示。刷新状态只读取本地日志，不会再次访问领取接口，也不能替代微信端核实未知结果。

## 协议兼容与验证边界

当前协议源码真正注册的组合领取路由为 `/api/TenPay/AutoHongBao`（SDK 基础地址已含 `/api` 时使用相对 `/TenPay/AutoHongBao`）。SDK / Swagger 中旧的 `OpenHongBao` 名称与注册表不一致，因此使用专用、限时且不跟随重定向的请求，而不调用旧 SDK 包装器。HTTP 404 / 405 明确提示路由不可用，不尝试另一个可能再次领取的接口。

Go 实现可能在 JSON 解析失败时仍返回外层成功、内层零值对象，因此不能仅根据 `Code=0` / `Success=true` 显示成功。当前实现严格要求实际回执，宁可显示未知。

自动化测试使用合成 XML、模拟微信响应、临时 SQLite 和本机 HTTP / 浏览器，**不打开任何真实红包**。尚未以真实账户验证协议端领取是否成功；实际行为还取决于当前服务端版本及微信风控。演示模式禁用领取，发布 / 更新代码本身也不会触发领取。
